Git vs GitHub

Git

  • A software
  • It is installed locally and runs on your computer
  • Tracks every change to your files (version control)

GitHub

  • A service
  • It is hosted on the web and backup in the cloud
  • A website that hosts Git repositories
  • Collaboration, sharing, websites

An analogy with R

The engine The friendly interface
Analysing data R RStudio
Version control Git GitHub Desktop
  • R and Git do the actual work, and can be used on their own by typing commands
  • RStudio and GitHub Desktop are apps that make them easier to use, with buttons instead of commands
  • GitHub Desktop comes with Git built in, so you only install one thing
  • GitHub (the website) is where your projects are stored online and shared

Why bother?

  • No more analysis_final_v2_REALLY_final.R
  • Go back to any previous version
  • Work with others without overwriting each other
  • Share your code & data (open science!)
  • Free websites with GitHub Pages (e.g., The REBEL lab)

Key concepts

Vocabulary

Term Meaning
Repository (repo) A project folder tracked by Git
Commit A snapshot of your files at a point in time
Clone Copy a repo from GitHub to your computer
Push / Pull Send / receive changes to / from GitHub
Branch A parallel line of work
Pull request (PR) A request to merge changes into another branch

The basic workflow

  1. Pull any changes from GitHub first, in case someone else made them
  2. Edit your files as usual: code, data, text…
  3. Commit: save a snapshot of your changes on your computer, with a short message
  4. Push your commits to GitHub
  5. Check your changes are on github.com

Tip

Commit little and often, and push at least at the end of every day.

The workflow at a glance

Getting started

Setup

  1. Create a free account at github.com
  2. Install GitHub Desktop (Git comes included)
  3. Open GitHub Desktop and sign in with your GitHub account
  4. Check your name and email under File ➜ Options ➜ Git (Mac: GitHub Desktop ➜ Settings ➜ Git)

Create a repository

  • On github.com, click New ➜ give it a name
  • Tick Add a README file
  • Click Create repository

Copy it to your computer (clone)

  • In GitHub Desktop: File ➜ Clone repository
  • Pick your repository from the list
  • Choose where to save it (Local path)
  • Click Clone

Save your changes (commit)

  • Edit and save your files as usual
  • The Changes tab shows what has changed
  • Tick the files you want to include
  • Write a short message in the Summary box
  • Click Commit to main

Tip

Commit little and often, with messages that explain why.

Send your changes to GitHub (push)

  • Click Push origin at the top of the window
  • Your commits are now on github.com
  • The History tab shows all your past commits

Get changes from GitHub (pull)

  • Click Fetch origin to check for new changes
  • If there are any, the button changes to Pull origin ➜ click it
  • Always pull before you start working
  • Especially when collaborating or using multiple computers

Ignoring files

Some files should not be tracked: large data, outputs, passwords 🔒

  • In the Changes tab, right-click a file
  • Choose Ignore file (or Ignore all .xxx files)
  • GitHub Desktop adds it to a .gitignore file for you

Collaborating

Branches

  • Click Current branch ➜ New branch, give it a name
  • Click Publish branch to send it to GitHub

Pull requests

  1. Commit and push your work on your branch
  2. Click Create Pull Request (opens github.com)
  3. Others review and comment
  4. Merge into main ✅

Hands-on

Exercise

  1. Create a new repository on github.com
  2. Clone it with GitHub Desktop
  3. Edit the README.md file
  4. Commit and push your changes
